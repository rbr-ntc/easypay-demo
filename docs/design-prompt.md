# Дизайн-промт для экранов EasyPay

Документ-источник для генерации макетов экранов в дизайн-инструменте (Claude Design / Figma AI / v0 и т.п.).
Дизайн-систему (цвета, шрифты, скругления) ты выбираешь сам — здесь намеренно оставлены плейсхолдеры
`{{...}}`, всё остальное (структура экранов, контент, состояния, поведение) задано жёстко, чтобы демо
получились консистентными.

> Поток обновлён под реальный dine-in сценарий: заказ → отправка на кухню → статус → оплата в конце.
> Отдельного экрана «выбор персоны» больше нет — имя спрашивается инлайн при первом добавлении блюда.

---

## 0. Как пользоваться этим файлом

1. Сначала подставь свою дизайн-систему в блок **«Глобальные параметры»** (один раз).
2. Для каждого экрана есть готовый **промт-блок** — копируй его целиком в дизайн-инструмент.
3. Каждый блок самодостаточен: содержит цель экрана, layout, список компонентов, **реальные демо-данные**
   (чтобы макет не был пустым) и список состояний.
4. Демо-данные общие во всех экранах — один и тот же стол, одни и те же гости и блюда, чтобы презентация
   выглядела как единый сквозной сценарий.

## 1. Глобальные параметры (подставь свою дизайн-систему)

```
ПРОДУКТ: EasyPay — заказ и оплата в ресторане по QR с привязкой блюд к персонам.
ПЛАТФОРМА: гостевой экран — мобильный web-app (PWA), портрет, 390×844 (iPhone 14/15 база).
           планшетный экран — 1280×800, ландшафт (режим официанта).
ЯЗЫК ИНТЕРФЕЙСА: русский (основной), валюта ₽ (формат «1 290 ₽», без копеек где целое).
ТОН: современный, лёгкий, «без трения» — сразу в меню, заказ и оплата без барьеров.

ДИЗАЙН-СИСТЕМА (подставить):
- Основной цвет (brand): {{PRIMARY}}
- Акцент СБП (приоритетный способ оплаты — должен визуально выделяться): {{SBP_ACCENT}}
- Нейтральная палитра / фон / поверхности: {{NEUTRALS}}
- Семантика: success {{SUCCESS}}, warning {{WARNING}}, error {{ERROR}}
- Шрифт заголовков / текста: {{FONT}}
- Радиус скруглений, тени, плотность: {{RADIUS/SHADOW/DENSITY}}
- Стиль иконок: {{ICONS}}

АВАТАРЫ ПЕРСОН (ВАЖНО): НЕ эмодзи и НЕ буквы A/B/C, а милые иллюстрированные ЗВЕРЮШКИ
из бесплатного/доступного набора (напр. лиса, медведь, панда, енот, сова, кот).
У каждой персоны — свой зверь + свой цвет. Подобрать единый стиль иллюстраций.

ПЕРСОНЫ ЗА СТОЛОМ (используются на всех экранах):
- Аня 🦊 (лиса)
- Дима 🐻 (медведь)
- Лена 🐼 (панда)
- новый гость — пустой слот «＋» (зверь назначается при создании)
(эмодзи выше — только пометка для генератора, в макете рисуем иллюстрации зверей)

ДЕМО-ЗАКАЗ (Стол №12, зал «Терраса», официант Максим):
- Том ям ............ 690 ₽   → Аня
- Пад тай ........... 600 ₽   → Дима
- Стейк рибай ..... 1 290 ₽   → Лена
- Спринг-роллы .... 450 ₽   → ОБЩЕЕ (на троих)
- Лимонад х3 ....... 3×220 ₽ → ОБЩЕЕ
- Пицца «Маргарита» 890 ₽   → ОБЩЕЕ (на троих)
ИТОГО по столу: 4 580 ₽.
Доля Ани (своё + 1/3 общего): 690 + (450+660+890)/3 = 690 + 666,67 ≈ 1 357 ₽.
```

## 2. Гостевой web-app — 9 экранов

### Экран 1 — Вход по QR / приветствие + онбординг

```
ЦЕЛЬ: гость отсканировал QR на столе и попал в web-app без установки. Сразу дать контекст
       («какой стол») и одной подсказкой объяснить модель «каждый со своего телефона».

LAYOUT (моб., портрет):
- Верх: логотип ресторана.
- КРУПНО: «Стол №12 · Терраса».
- Заголовок «Добро пожаловать!»; подзаголовок «Закажите и оплатите со своего телефона —
  без приложения и очереди».
- Онбординг-подсказка (карточка/баббл, показывается 1 раз):
  «Можно заказать за весь стол отсюда. А если каждый хочет заказать сам — пусть отсканирует
   этот же QR со своего телефона.»
- Чип «Без установки».
- Переключатель языка (RU / EN).
- Низ: крупная primary-кнопка «Открыть меню».
- Под кнопкой — мелкая строка про согласие на обработку данных (152-ФЗ) со ссылкой.

СОСТОЯНИЯ:
- loading (определяем стол по QR) — скелетон с текстом «Открываем ваш стол…».
- ошибка «QR недействителен» — иллюстрация + кнопка «Позвать официанта».
- возврат в существующую сессию (гость уже заказывал с этого телефона) — «С возвращением,
  🦊 Аня! Продолжить заказ» вместо приветствия новичка.
```

### Экран 2 — Меню (точка входа, без барьера)

```
ЦЕЛЬ: гость сразу видит меню. Имя НЕ спрашиваем заранее — только при первом добавлении блюда.

LAYOUT:
- Sticky-шапка: «Стол №12» + иконка корзины с бейджем суммы (пока 0).
  Если имя уже введено — слева аватар-зверь и имя («🦊 Аня»).
- Горизонтальные табы категорий: Супы · Основное · Пицца · Напитки · Десерты.
- Поиск (иконка).
- Карточки блюд: фото, название, краткое описание, цена, кнопка «＋».
  Пример: «Том ям · Острый суп с креветками и кокосовым молоком · 690 ₽».
- Позиция из стоп-листа: затемнена, бейдж «Нет в наличии», кнопка неактивна.
- Низ: плавающая кнопка «Корзина · 690 ₽ →» (появляется после первого добавления).

ПОДЭКРАН (модалка блюда с модификаторами):
- Фото, описание, выбор модификаторов («Острота: слабо/средне/остро», «Доп. креветки +150 ₽»),
  счётчик количества, заметка к кухне.
- Кнопка «Добавить · 690 ₽».

СОСТОЯНИЯ: загрузка меню (скелетоны), пустая категория, обновление стоп-листа
(тост «Позиция X закончилась»).
```

### Экран 3 — Имя + аватар (инлайн, при первом добавлении блюда)

```
ЦЕЛЬ: легко закрепить заказ за персоной ровно в тот момент, когда это впервые нужно.
       Это НЕ отдельный экран-барьер, а bottom-sheet поверх меню.

LAYOUT (bottom-sheet):
- Заголовок «За кем записать заказ?».
- Поле имени (плейсхолдер «Ваше имя», система предлагает; можно оставить — будет «Гость 2»).
- Ряд аватаров-зверюшек на выбор (лиса/медведь/панда/енот/сова/кот…), один выбран по умолчанию.
- Если за столом УЖЕ есть персоны — свёрнутая строка «или записать за: 🦊 Аня · 🐻 Дима»
  (на случай «закажу и за жену»).
- Кнопка «Готово» → блюдо падает в корзину выбранной персоны.

СОСТОЯНИЯ: первый гость за столом (списка других нет), добавление заказа за другую персону.
```

### Экран 4 — Заказ / корзина (вид C: своё + свёрнутый весь стол)

```
ЦЕЛЬ: показать СВОЙ заказ крупно, дать прозрачность по столу и подвести к отправке на кухню.

LAYOUT:
- Заголовок «Заказ · Стол №12».
- Блок «Мой заказ» (крупно, с аватаром персоны):
    🦊 Аня
        • Том ям — 690 ₽   [изменить] [удалить]
    Подытог: 690 ₽
- Сворачиваемый блок «Весь стол ▼» (по умолчанию свёрнут, разворот тапом):
    🐻 Дима — Пад тай — 600 ₽
    🐼 Лена — Стейк рибай — 1 290 ₽
    Итог по столу: 4 580 ₽
- Блок «Общие блюда» (визуально отделён, иконка «на компанию»):
    • Спринг-роллы — 450 ₽ · Лимонад ×3 — 660 ₽ · Пицца «Маргарита» — 890 ₽
    Деление (сегмент-контрол): [ Поровну ] [ По долям ] [ Назначить ]
    Подпись: «Общее: 2 000 ₽ · поровну по 666,67 ₽ на троих».
- Две кнопки: secondary «Дозаказать» (→ меню) и primary «Отправить на кухню».

СОСТОЯНИЯ:
- пустая корзина — «Пока пусто, добавьте блюда».
- позиция уже отправлена на кухню — лочится, бейдж «Готовится», удаление только через
  официанта (тултип).
- редактирование общего блюда «Назначить» — чек-лист персон, кому делить.
```

### Экран 5 — Отправка на кухню (гибрид + подтверждение)

```
ЦЕЛЬ: ключевой момент сценария. Дать выбор «отправить своё» или «за весь стол» с защитой
       от преждевременной отправки.

LAYOUT (модалка подтверждения):
- Заголовок «Отправить заказ на кухню?».
- Две опции:
    ● Отправить мой заказ (🦊 Аня · 1 поз. · 690 ₽)   ← по умолчанию
    ○ Отправить за весь стол (3 поз. + общие · 4 580 ₽)
- Если выбрано «за весь стол» И не все отправляли — ПРЕДУПРЕЖДЕНИЕ (warning-баннер):
    «🐻 Дима ещё не отправлял свой заказ. Все точно выбрали?»
- Чек-строка «Я всё выбрал(а)».
- Кнопки: primary «Отправить», text «Ещё подумаю».

СОСТОЯНИЯ: все уже отправили (опция «за весь стол» неактивна/скрыта), отправка в процессе
(лоадер «Передаём на кухню…»), ошибка связи с кассой (retry).
```

### Экран 6 — Статус заказа (НОВЫЙ — между кухней и оплатой)

```
ЦЕЛЬ: подтвердить, что заказ ушёл и готовится; не давить оплатой; оставить дозаказ доступным.

LAYOUT:
- Крупная позитивная иллюстрация + статус-степпер:
    ✅ Принят  →  👨‍🍳 Готовится  →  🍽 Подано
- Большой тёплый заголовок «Заказ принят. Приятного аппетита!».
- Список позиций со статусами (по персонам), таймер-ожидание опционально.
- Кнопка «Дозаказать» (остаётся доступной весь вечер → возвращает в меню).
- Внизу СПОКОЙНАЯ (не агрессивная) кнопка «Оплатить» — платят в конце, не торопим.
- Если кто-то ещё не отправил заказ — мягкая подсказка «🐻 Дима ещё выбирает».

СОСТОЯНИЯ: готовится / частично подано / всё подано; появление дозаказа отдельной «волной»
(новый блок «Волна 2»); push/баннер «Ваше горячее готово».
```

### Экран 7 — Оплата

```
ЦЕЛЬ: гость выбирает ЧТО платит и КАК. СБП — приоритетный способ (визуально первый).

LAYOUT:
- Заголовок «Оплата».
- Выбор объёма оплаты (карточки-радио):
    ● Оплатить своё — 1 357 ₽ (по умолчанию; «690 ₽ ваше + 666,67 ₽ доля общего»)
    ○ Разделить поровну — 1 526,67 ₽
    ○ Оплатить весь стол — 4 580 ₽
- Сводка выбранного (раскрывающаяся детализация).
- Способы оплаты (СБП ПЕРВЫМ, акцентный стиль {{SBP_ACCENT}}, бейдж «Рекомендуем»):
    ◉ СБП — оплата по QR / кнопке банка
    ○ Банковская карта
    ○ T-Pay / SberPay / Mir Pay / Yandex Pay (ряд иконок-кошельков)
- Чекбокс «Отправить чек на email/телефон» + поле.
- Низ: primary «Оплатить 1 357 ₽».

СОСТОЯНИЯ:
- частичная оплата: баннер «🐻 Дима уже оплатил свою часть. Осталось 3 313,33 ₽»
  (доля Димы = 600 + 666,67 = 1 266,67 ₽; суммы опций всегда пересчитываются от остатка).
- СБП-флоу: динамический QR + кнопка «Открыть приложение банка» + таймер ttl.
- обработка — фуллскрин-лоадер «Проводим оплату…».
- ошибка платежа — понятный текст + «Повторить» (идемпотентно, позиции не задваиваются).
```

### Экран 8 — Чаевые

```
ЦЕЛЬ: чаевые отдельной транзакцией напрямую официанту (не в счёт ресторана).

LAYOUT (после успешной оплаты или встроено в шаг оплаты):
- Карточка официанта: фото, имя «Максим», рейтинг ⭐ 4.9.
- Заголовок «Поблагодарить официанта?».
- Пресеты-чипы: [ 5% ] [ 10% · популярно ] [ 15% ] [ Своя сумма ]. Под выбранным — «135 ₽».
- Поле «Своя сумма» (при выборе).
- Подпись мелким: «Чаевые поступают напрямую официанту».
- Кнопки: primary «Оставить 135 ₽», text «Пропустить».

СОСТОЯНИЯ: ввод своей суммы, пропуск, несколько официантов на стол (селектор).
```

### Экран 9 — Подтверждение / чек / отзыв

```
ЦЕЛЬ: финал «всё готово» за 10 секунд: статус, чек, отзыв.

LAYOUT:
- Крупная success-галочка + «Оплачено · 1 357 ₽» (анимация).
- Если оставлены чаевые — «+ 135 ₽ чаевых официанту Максиму».
- Карточка чека: «Фискальный чек отправлен» + «Открыть чек» и «Мои чеки онлайн (ФНС)».
- Блок отзыва: «Как всё прошло?» — 5 звёзд + чипы («Вкусно», «Быстро», «Уютно») + коммент.
- Низ: primary «Готово», secondary «Заказать ещё» (если стол открыт → меню).

СОСТОЯНИЯ:
- ожидание подтверждения кассы (лоадер «Подтверждаем у кассы…»).
- частичная оплата: «Ваша часть оплачена. По столу осталось 3 223 ₽» + «Передать ссылку соседу».
- отзыв отправлен — мягкая благодарность.
```

```
ЦЕЛЬ: устройство у официанта; обзор стола, статусы заказов и оплат, дозаказ, помощь.

LAYOUT (двухколоночный):

СОСТОЯНИЯ: офлайн-буфер («Нет связи с кассой — режим просмотра»), синхронизация, стол закрыт.

        статус «Ожидаем оплату…» → success. Кнопка «Отправить чек».

## 4. Сквозные требования к макетам (для всех экранов)

```
- Привязка «блюдо → персона» всегда читается аватаром-ЗВЕРЁМ + цветом + именем (не эмодзи/буквы).
- Меню — точка входа; никаких барьеров «представься» перед просмотром меню.
- «Отправить на кухню» и экран статуса — обязательная часть потока (не только оплата).
- СБП всегда визуально приоритетнее карты (порядок, бейдж, акцентный цвет).
- Состояния обязательны для демо: loading (скелетоны), empty, error (понятный повтор),
  offline-деградация («только просмотр»).
- Доступность: контраст AA, тач-таргеты ≥ 44px, крупные суммы и кнопки.
- Тон копирайта — дружелюбный, короткий; суммы в ₽ с пробелом-разделителем.
- Низ моб-экранов: «липкая» primary-кнопка действия (thumb-friendly).
```

## 5. Рекомендуемый набор макетов для презентации (демо)

Сквозной сценарий «отсканировал → меню → заказал за себя → отправил на кухню → статус →
оплатил своё по СБП → чаевые → чек»:

1. Экран 1 (вход + онбординг) → 2 (меню) → 3 (имя+зверь при добавлении) → 4 (корзина, вид C) →
   5 (отправка на кухню с предупреждением) → 6 (статус «готовится, приятного аппетита») →
   7 (оплата «своё» по СБП) → 8 (чаевые 10%) → 9 (готово + отзыв).
2. + Планшет А (обзор стола со смешанными статусами заказа/оплаты) — «вид ресторана».

Этого хватает на слайды презентации и на кликабельный прототип демо-приложения.
```
