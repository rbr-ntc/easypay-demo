# Что умеет сервер и что из этого видит человек

Отдельный документ появился после простого наблюдения владельца: агенты звали
официанта «за водой», а у гостя на экране была одна кнопка «Позвать официанта».
Возможность существовала в API и не существовала для человека.

Это не единичный случай, а класс дефектов, который не ловится ни тестами API
(они дёргают ручку напрямую), ни глазами (нельзя увидеть то, чего на экране нет).
Ловится он только сверкой: **у каждой возможности сервера должно быть место,
откуда её вызывает человек — либо явная пометка, что места нет и почему.**

Правило простое: **добавил действие на сервере — впиши строку сюда.** Если в
колонке «где на экране» стоит прочерк, значит функции для ресторана ещё нет,
сколько бы тестов её ни покрывало.

## Гость

| Действие | Что делает | Где на экране |
|---|---|---|
| `join` | садится за стол, называет имя, зверя и **аллергии** | лист имени при первом заказе |
| `lines` | добавляет блюдо с модификаторами и **комментарием** | карточка блюда |
| `lines` + `confirmAllergen` | осознанно берёт блюдо со своим аллергеном | красное предупреждение в карточке |
| `remove` | убирает из корзины неотправленное | корзина |
| `send` | отправляет на кухню (своё или за стол) | лист отправки |
| `cancelMine` | отменяет своё, пока кухня не взялась | «отменить» у позиции в статусе |
| `pay` | платит: своё, поровну, за стол; СБП или карта | экран оплаты |
| `cashIntent` | просит официанта принять наличные | «Заплачу наличными» на экране оплаты |
| `tip` | чаевые официанту мимо счёта | экран чаевых |
| `call` | зовёт официанта: помощь, счёт, вода, **текст** | лист вызова |

## Кухня

| Действие | Что делает | Где на экране |
|---|---|---|
| `start` | берёт позицию в работу | «В работу» на тикете |
| `ready` | готово, стоит на раздаче | «Готово» → полоса «На раздаче» |
| `serve` | унесли гостю | «Унёс гостю» на раздаче |
| `dismiss` | подтверждает, что снял отменённое с плиты | «Снял с плиты» на карточке отмены |

## Зал

| Действие | Что делает | Где на экране |
|---|---|---|
| `ack` | снимает вызов гостя (на любом столе) | чип «требуют внимания» в зале |
| `cash` | подтверждает, что физически взял наличные | карточка «платит наличными» на экране стола |
| `close` | закрывает стол | кнопка на экране стола |
| `clean` | стол убран, можно сажать | «Убрано» на грязной карточке в зале |
| `reset` | освобождает стол принудительно | экран стола, под правами менеджера |
| `GET /api/log` | журнал смены | зал, под правами менеджера |
| `GET /api/shift/checks` | реестр чеков и сверка кассы | зал, под правами менеджера |

## Известные прочерки

Сюда попадает то, что сервер умеет, а человек — нет. Список должен быть коротким
и каждый пункт — объяснённым.

- **`pay` со `scope: equal`** («поровну») — в API есть, на экране гостя выбор из
  «своё» и «за стол». Делить поровну при разных заказах — почти всегда не то,
  чего хочет гость; оставлено в API для планшета официанта.
- **Выбор способа оплаты `method`** доезжает до сервера, но фискального чека нет:
  до интеграции с кассой это метка в отчётности, а не платёжный маршрут.

## Как это проверять

Раз в смену агентов один тестировщик работает **только глазами в браузере** —
без curl. Его задача не «работает ли ручка», а «может ли этим воспользоваться
человек». Всё, что он не смог найти на экране, попадает в прочерки выше.
