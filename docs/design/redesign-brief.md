# Бриф на редизайн 4.0

Для Claude Design. Вместе с брифом передаётся кодовая база — всё, что здесь сказано
про «сейчас», проверяется по файлам, ссылки даны.

Продуктовая часть (что должно появиться и зачем) — `docs/product/backoffice-plan.md`.
Прошлый хендофф, по которому сделан текущий интерфейс, — `docs/design/easypay-3.0-handoff.md`.

---

## 1. Продукт в двух абзацах

EasyPay — заказ и оплата в ресторане по QR. Гость сканирует код на столе, заказывает
с телефона, блюдо сразу привязано к нему. Это и есть главное отличие от «разделить
счёт в конце»: к моменту оплаты каждый уже знает свою сумму. Общие блюда делятся
между теми, кто сидел за столом в момент отправки на кухню.

Три роли и три поверхности:
- **гость** — телефон, без установки, без регистрации;
- **смена** — официант, повар, менеджер: зал, кухня, экран стола; планшет или телефон,
  на ногах, вход по PIN;
- **кабинет** — менеджер и владелец: смены, чеки, долги, меню, персонал. Компьютер.
  **Этой поверхности пока нет вовсе** — её надо спроектировать с нуля.

## 2. Почему редизайн, если 3.0 только что сделан

По результатам ручного теста владельца продукта:

- с телефона интерфейс «не сексуальный»: тяжело, темно, всё одинаково жирное;
- у персонала вся бухгалтерия лежит лентой в правой колонке зала;
- нет закрытия смены, истории смен, разбора долгов, редактора меню — это новые экраны.

И технически дизайн-система 3.0 до кода доехала плохо. Замер по `apps/web/src`:

| Что | Сколько |
|---|---|
| Уникальных hex-цветов прямо в компонентах | **77** (445 вхождений) |
| Инлайн-стилей `style={{…}}` | **278** |
| `rgba(…)` в компонентах | 87 |
| Разных размеров шрифта | **24** — от 11 до 62 px |
| Начертания | extrabold ×100, bold ×92, semibold ×80, medium ×3 |

То есть тема daisyUI (`apps/web/src/theme.css`) описывает 18 цветов, а экраны живут
на 77 своих. Иерархии в шрифтах нет: три жирных начертания на всё. **Первая задача
редизайна — дизайн-система, которую код сможет держать**, а не новые картинки поверх
старой каши.

## 3. Ограничения, которые не обсуждаются

**Стек.** React 18, Tailwind CSS 4, daisyUI 5 (тема в `apps/web/src/theme.css`),
без роутера (hash), без стейт-менеджера. Шрифты лежат локально
(`apps/web/public/fonts`). Токены в макете должны лечь в формат темы daisyUI:
`--color-base-100…300`, `primary`, `secondary`, `accent`, `neutral`, `info/success/
warning/error` и их `-content`, `--radius-*`, `--size-*`.

**Устройства.**
- гость: **Android 412×915 — главный кадр**, плюс 360 (маленький), iPad 768/1024,
  монитор 1440 (открывают ссылку с ноутбука — уже чинили «разлетающуюся» вёрстку);
- смена: планшет 1024×768 и 768×1024, телефон официанта 412;
- кабинет: монитор 1440, ноутбук 1280.

**Железо.** Средний Android в зале с плохой сетью. **WebGL-фоны, шейдеры, частицы
и эффекты курсора в гостевом потоке — нельзя**: сажают батарею и тормозят. `backdrop-
filter` уже используется, дороже не делать.

**Доступность.** WCAG AA: 4.5:1 для текста мельче 18.66 px, 3:1 для крупного. Это уже
проверялось симуляцией на фото — стекло поверх светлых кадров чуть не провалило
подписи. Цвет текста поверх фото задавать с запасом.

**Продуктовые инварианты** (из `CLAUDE.md`):
- аватары гостей — **иллюстрированные звери** (`apps/web/src/avatars.tsx`), не эмодзи
  и не буквы;
- интерфейс **не считает деньги сам** — все суммы приходят с сервера; в макете не
  должно быть мест, где клиент «прикидывает» сумму;
- СБП — главный способ оплаты; чаевые — напрямую официанту, мимо счёта;
- оплата в конце, по умолчанию;
- у каждого блюда — аллергены; предупреждение аллергику обязательно.

## 4. Что оставить из 3.0, что пересмотреть

**Оставить как идею, переосмыслить исполнение:**
- палитра «Ель и лайм» узнаваема; вопрос в пропорциях — сейчас тёмно-зелёного
  слишком много для еды;
- «моменты» шрифтом с засечками (Instrument Serif) — сумма к оплате, «Спасибо»,
  номер стола; основной шрифт Manrope;
- стекло поверх фото — но не на 40 % кадра.

**Пересмотреть:**
- **шкала типографики:** не больше 7 размеров и **два** начертания на весь продукт;
- **плотность меню:** сейчас карточка блюда 280 px, на экран влезает 2,5 блюда, всё
  меню — около 10 000 px ленты;
- **шапка меню:** ~200 px (22 % экрана), не сжимается при прокрутке;
- **две системы карточек рядом** (фото на стекле / тёмная строка с полосатой
  заглушкой) — выглядит, будто часть меню сломана. 9 из 42 блюд без фото — нужна
  карточка без фото, которая выглядит задуманной;
- **тёмная тема гостевых экранов** — в 3.0 была заявлена, не сделана;
- **кабинет** — вероятно, светлая «рабочая» версия палитры: на мониторе живут часами.

Подробные наблюдения по гостю — `docs/product/backoffice-plan.md` §7.

## 5. Что нужно на выходе

**5.1. Токены.** Готовый блок темы daisyUI для светлой и тёмной версии, плюс:
шкала шрифтов (размер / межстрочный / начертание), радиусы, тени, отступы. Каждый цвет
текста — с указанием, на каком фоне он проходит AA.

**5.2. Компоненты — с состояниями** (обычное, нажато, неактивно, загрузка, ошибка):

*Общие:* кнопки (главная, вторичная, опасная, текстовая), поле ввода, поиск, чип/
фильтр, сегмент-переключатель, тумблер, степпер количества, бейдж статуса, тост,
модалка (лист снизу на телефоне, окно на планшете и мониторе — так уже сделано),
пустое состояние, скелетон загрузки, аватар-зверь, баннер «нет связи».

*Гость:* карточка блюда крупная, строка блюда с миниатюрой, строка блюда без фото,
карточка «рекомендуем», шапка меню в развёрнутом и сжатом виде, позиция в «Столе»
(черновик / на кухне / подано / отменено), прогресс блюда, сумма «моё / стол»,
выбор способа оплаты, чаевые, чек.

*Смена:* карточка стола в зале (свободен, сели, готовится, подано, платят, оплачен,
грязный, есть вызов, долг), тикет кухни (новый, в работе, готово, просрочен),
тумблер стоп-листа, единая шапка-навигация.

*Кабинет:* боковое меню, таблица с фильтрами и сортировкой, панель деталей справа,
KPI-плитка, график по часам, мастер из шагов, карточка долга с действиями, форма
блюда, строка «требует решения».

**5.3. Экраны** — по приоритету в `docs/product/backoffice-plan.md` §10. Для каждого —
кадры 412 и 1440 (гость), 1024 (смена), 1440 (кабинет).

## 6. Готовые компоненты: React Bits и 21st.dev

Посмотрели обе библиотеки. Коротко: **брать точечно, в основном микро-взаимодействия
и компоненты кабинета**, а не эффектные фоны.

**React Bits** (reactbits.dev) — анимированные React-компоненты, ставятся исходниками
через реестр shadcn (подключается MCP-сервером shadcn, аккаунт не нужен). Часть
тянет `motion`, `gsap` или WebGL (`ogl`, `three`) — каждую надо проверять на вес.

Что может пригодиться (по названиям из каталога — демо каждого надо смотреть):

| Где | Компонент | Зачем |
|---|---|---|
| Гость, оплата | Slide Commit / Hold Button | подтверждение оплаты жестом — защита от случайного тапа |
| Гость, суммы | Count Up / Counter | сумма к оплате и остаток «докручиваются», а не прыгают |
| Гость, «Стол» | Swipe Row | убрать блюдо из черновика свайпом |
| Гость, «Стол» | Animated List | позиции появляются по одной, а не всей пачкой |
| Гость, успех | Spring Check | «оплачено» |
| Гость, вызов | Call Chip | вызов официанта |
| Гость, отзыв | Peek Rating | оценка после оплаты |
| Гость, стекло | Glass Surface / Fluid Glass | референс для стекла поверх фото; устройство и вес не проверяли — на Android мерить |
| Смена | Squish Switch | стоп-лист в один тап |
| Смена | Rubber Segment | «Мои столы / Весь зал» |
| Смена | Status Mark | статус стола и тикета |
| Кабинет | Line Sidebar | боковое меню |

**Не брать в гостевой поток:** все Backgrounds (Silk, Aurora, Plasma и т. п. — WebGL),
все Cursor-эффекты (на телефоне курсора нет), 3D и частицы.

**21st.dev** — большой каталог сообщества: дашборды (~400), таблицы (~310), графики
(~250), боковые меню (~95), KPI-плитки (~150), выбор дат, пустые состояния, степперы.
Это **материал для кабинета**. Оговорка: почти всё там построено на shadcn/ui (Radix +
свои токены), а у нас daisyUI — компонент придётся либо переводить на наши токены,
либо заводить shadcn рядом. Лучше брать как референс вёрстки, а не копировать код.
Свой MCP у 21st.dev есть, но нужен их аккаунт и ключ; условия тарифа — на их сайте, мы не проверяли.

**Просьба к дизайну:** если в макете используется компонент из этих библиотек —
подписать его название, чтобы при переносе в код не угадывать.
