# Handoff: EasyPay 3.0 — «Ель и лайм»

## Overview

Полный редизайн визуального языка и гостевого потока EasyPay (заказ и оплата в ресторане по QR с привязкой блюд к персоне в момент заказа). Причина работы: интерфейс собран на стоковой теме daisyUI, из-за чего выглядит как черновик, а поток разведён на семь экранов, где гость не понимает, что уже ушло на кухню, а что нет.

Что меняется:

1. **Визуальная система.** Крем + глубокий еловый + кислотный лайм, крупная типографика Manrope, акцентный Instrument Serif на суммах, стеклянные карточки поверх фотографий еды.
2. **Поток гостя.** Вместо `welcome → menu → cart → status → payment → tips → done` — три шага: **Меню → Стол → Оплата**. Корзина и статус слиты в один экран «Стол»: черновик отделён пунктирной рамкой «ещё не отправлено на кухню», отправленное показывает стадию (`queued → cooking → ready → served`), общее блюдо показывает личную долю, ниже — «кто что должен».
3. **Закрытие долгов интерфейса.** Спроектированы поверхности для всего, что сервер уже умеет, а UI не показывал: вход без `?t=`, QR-тент, блок по аллергену с заменой модификатора, вызов официанта с причиной, наличные в два шага, ошибка платежа с повтором по тому же `idemKey`, отмены и списания на кухне, стоп-лист, переплата и принудительное закрытие стола, состояния связи, RU/EN, апселлы.

## About the Design Files

Файлы в этом бандле — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие желаемый вид и поведение, а **не production-код для копирования**.

Задача: **воссоздать эти экраны внутри существующего окружения `apps/web`** — React 18 + TypeScript, Vite, Tailwind v4 + daisyUI 5, состояние в одном контексте `src/store.tsx`, синхронизация по SSE, хеш-роутинг без роутера. Используйте установленные в репозитории паттерны и примитивы (`src/ui.tsx`, `src/avatars.tsx`, `src/lineStage.ts`, `src/format.ts`), а не инлайн-стили из HTML-прототипа. Инлайн-стили в прототипе — следствие среды, в которой он сделан; в проекте им соответствуют классы daisyUI + токены темы из приложенного `theme.css`.

Ничего в `packages/domain`, `apps/api` и денежной модели менять не нужно: редизайн не трогает правила расчёта. Все суммы на макетах взяты из `packages/config/menu.json`, столы и зоны — из `packages/config/hall.json`.

## Fidelity

**High-fidelity.** Финальные цвета, типографика, отступы, радиусы, состояния. Воссоздавать пиксельно, но средствами daisyUI-темы: сначала подключить `theme.css`, затем переводить экраны — тогда большая часть значений придёт из темы автоматически.

Контраст проверен по WCAG AA (4.5:1 для текста < 18.66px, 3:1 для крупного). Токены подобраны на грани — **не осветляйте muted-тона и не заменяйте их на `text-base-content/60`**: прозрачность в этой палитре даёт 2.4–3.1:1 на кремовом фоне, а такие подписи стоят на экранах списания денег.

### Типографика

- **Manrope** 400/500/600/700/800 — весь интерфейс. Google Fonts.
- **Instrument Serif** 400 — только «моменты»: крупная сумма к оплате, выручка смены, «Спасибо», номер стола на тенте. Нигде мельче 34px.
- Шкала: 30/27 (заголовок экрана, `800`, `letter-spacing:-0.025em`), 21/20 (заголовок блока), 19/17/16 (названия блюд и строк, `700–800`), 15 (тело, `500`, `line-height:1.5`), 13 (вторичное, `600`), 11 (эйбрау: `700`, `letter-spacing:0.14em`, `text-transform:uppercase`).
- Числа в таблицах и деньгах — `font-variant-numeric: tabular-nums`.
- **Суммы не должны переноситься.** В разрядах — NBSP (`1 660 ₽` с U+00A0 и перед `₽`) либо `white-space: nowrap`. Реальный дефект из ревью: «осталось 1» на одной строке и «770 ₽» на другой. `fmt()` из `src/format.ts` использует `toLocaleString('ru-RU')`, который даёт узкий неразрывный пробел — проверьте, что он не заменяется обычным.

### Геометрия и тени

- Радиусы: карточка/шторка `22px` (`--radius-box`), поле/кнопка `16px` (`--radius-field`), чип/аватар `999px`, стеклянная карточка `20px`, фрейм телефона `26px`.
- Высоты: главная кнопка `60px`, вторичная `56px`, поле `48–56px`, чип `42–46px`, круглая иконка-кнопка `44px`. **Минимум 44px для всего, во что попадают пальцем** — это уже зафиксировано в текущем коде комментариями (`size-11` = 44px), не откатывайте.
- Тени: карточка на креме `0 6px 18px -14px rgba(6,33,25,.4)`; главная кнопка `0 12px 26px -14px rgba(6,33,25,.9)`; sticky-футер `0 -14px 22px -18px rgba(6,33,25,.5)`.
- Отступы экрана: `20px` по горизонтали, `16px` сверху, `22px` снизу (плюс `env(safe-area-inset-bottom)`).

### Стекло (ключевой приём)

```css
/* НА ФОТО: скрим, потом стекло. Порядок обязателен. */
.scrim {                       /* лежит на <img>, попадает в backdrop-filter */
  background: linear-gradient(to top,
    rgba(6,33,25,.90) 0%, rgba(6,33,25,.78) 26%,
    rgba(6,33,25,.12) 62%, rgba(6,33,25,0) 82%);
}
.glass {
  background: linear-gradient(158deg,
    rgba(255,255,255,.17) 0%, rgba(255,255,255,.07) 55%, rgba(255,255,255,.11) 100%);
  border: 1px solid rgba(255,255,255,.30);
  backdrop-filter: blur(44px) saturate(1.5) brightness(.92);
  box-shadow: inset 0 1.5px 0 rgba(255,255,255,.38),
              inset 0 -1px 0 rgba(255,255,255,.08),
              0 18px 42px -20px rgba(4,18,13,.8);
}
```

Две ошибки, которые мы уже совершили и откатили:

1. **Светлый стоп градиента в текстовой зоне.** Блик должен быть хайрлайном (`inset 0 1.5px 0`), а не рампой на 38% высоты — иначе белое название падает до 1.5:1.
2. **Компенсация контраста альфой самой карточки.** `rgba(...,.84)` читается как чёрный прямоугольник и убивает эффект. Затемнять надо **фото под стеклом**, а не стекло.

Для карточек без фотографии (заглушка) скрим тоже нужен: за стеклом там почти белая штриховка.

## Секция 6a — остаток потока и движение

Девять экранов, без которых поток рвётся:

- `6a: СБП QR` — код в кремовой рамке на еловом, сумма 52px Instrument Serif, таймер жизни кода, «Оплатить другим способом». QR всегда чёрный на белом.
- `6a: Идёт оплата` — три шага списания (запрос ушёл → ждём подтверждение → запишем в счёт), спиннер + пульсирующее кольцо, сноска про идемпотентный ключ. Кнопки нет вовсе — уйти нельзя.
- `6a: Поиск` — результаты с подсветкой совпадения (`<mark>` лаймом), совпадение по составу, пустой результат с выходом на официанта. Искать надо по `name`, `desc` и `tags` из `menu.json`.
- `6a: Блюдо в стопе` — блюдо ушло в стоп, пока гость читал карточку: фото в грейскейле, бейдж «только что закончился», две замены по той же категории/тегам, предупреждение, что из черновика позиция тоже убрана.
- `6a: Клавиатура` — ввод «своей суммы» с открытой системной клавиатурой: главная кнопка приклеена к её верхней кромке, контент над ней прокручивается, быстрые суммы рядом. То же правило — для ввода имени и комментария повару.
- `6a: Чек и предоплата` — разделение «чек заказа» (наш, сразу) и «фискальный по 54-ФЗ» (его пробивает касса, состояние «ждём чек из кассы» с таймером) + переключатель «в конце / сразу» как настройка заведения (при предоплате «Отправить на кухню» → «Оплатить и отправить»).
- `6a: Отказ по роли` — 403 для повара на экране стола (права из `packages/domain/roles.js`) со списком доступного и отдельной плашкой сервисного входа по `mtoken` — сейчас мастер-токен невидим, и непонятно, почему у человека есть доступ.
- `6a: Возврат и вне плана` — диалог возврата переплаты (кому — последнему плательщику, чем — СБП или наличные из кассы, с записью в журнал и уменьшением `netRevenue`) и диалог добавления стола в `hall.json` (зона, посадка, официант; открытая сессия не прерывается).
- `6a: Анимации` — живая шпаргалка со всеми таймингами (ниже).

### Мотион-спек

Одно правило: движение объясняет изменение и не заставляет ждать. Всё длиннее 400 мс — только для того, чего гость ждал.

| Паттерн | Значения | Ключевые кадры |
| --- | --- | --- |
| Шторка снизу | 220 ms `cubic-bezier(.2,.8,.2,1)`, закрытие 160 ms | `translateY(26px) opacity 0` → `0 / 1` |
| Тост | вход 180 ms, держится 3 s, уход 140 ms | `translateY(-16px) scale(.96)` → `0` → `translateY(-10px) opacity 0` |
| Стадия блюда | 320 ms ease-out, `transform-origin:left` | `scaleX(0)` → `scaleX(1)` |
| Скелетон | 1.4 s linear infinite, показывать после 300 ms ожидания | `background-position 200% → -200%` на градиенте `#E3DCCB / #F7F2E7` |
| Успех | 500 ms `ep-rise` + кольцо 1.8 s ease-out | `scale(.5) opacity 0` → `scale(1.06)` → `1`; кольцо `scale(.85→1.7) opacity .55→0` |
| Нажатие | 120 ms | `scale(.955)` |
| Пульс ожидания | 1.6 s ease infinite | `opacity 1 → .45 → 1` — единственная бесконечная анимация: значит «человек ждёт сейчас» |
| Переход экранов | 200 ms ease-out вперёд, 160 ms назад | сдвиг 12 px + opacity; никаких слайдов на всю ширину |
| Пришло по SSE | появление строки 180 ms + подсветка фона 900 ms | чтобы было видно: изменилось само, а не от вашего действия |
| Кухня | только смена цвета тикета и появление карточки | мигающее у плиты — источник ошибок |

`@keyframes` готовы в `<helmet>` макета: `ep-sheet`, `ep-toast`, `ep-fill`, `ep-shimmer`, `ep-spin`, `ep-ring`, `ep-press`, `ep-rise`, `ep-breathe`. При `prefers-reduced-motion: reduce` остаются только смены цвета и прозрачности (правило уже есть в `apps/web/src/styles.css` — расширить его на новые имена).

## Interactions & Behavior
- **Один главный CTA на экран**, всегда в нижнем sticky-футере, всегда с суммой. Прокручивается только середина (`.ep-screen` / `.ep-scroll` из текущего `styles.css` остаются).
- **Черновик → кухня**: кнопка живёт внутри блока черновика И в футере (когда черновик единственное действие). Отправка ведёт на «Стол» с обновлённой стадией.
- **Стадии позиции** приходят с сервера: `sent → startedAt → readyAt → served`; подписи и цвета — единые (`src/lineStage.ts`). Не вводите новых слов: гость и персонал должны видеть одно название стадии.
- **Отмена своей позиции** доступна, пока `startedAt` пуст.
- **Оплата**: `scope` обязателен, сумму считает сервер (`amountFor` + клампинг остатком), клиент показывает `totals`. Идемпотентный ключ живёт до успешной оплаты — на экране ошибки повтор идёт с тем же ключом.
- **Наличные**: `cashIntent` (просьба, денег в счёте нет) → официант подтверждает `cash`. Гость может отменить просьбу.
- **Аллерген**: `409` от сервера → шторка с заменой; `confirmAllergen: true` только по осознанному действию.
- **Апселл** показывается один раз после первой подачи, не во время ожидания.
- **Анимации**: `ep-rise` (галочка успеха, 0.5s ease), `ep-breathe` (пульс точки/скелетона, 1.6s), переходы состояний 150–200ms ease-out. `prefers-reduced-motion` — отключать (правило уже есть в `styles.css`).
- **Фокус**: видимая обводка `2px #062119` (на еловом — `2px #D5F94E`) с отступом 2px. Сейчас в коде фокус-стили не заданы явно — это добавить.

## Что уже реализовано, а что нет

В секции `#5a` смешаны два типа экранов, и это важно для планирования:

**Редизайн существующего** (компонент есть, выглядит как отладочная таблица):
- `5a: Реестр чеков` — `apps/web/src/hall/ShiftChecks.tsx` + `GET /api/shift/checks`. ## Что требует новых эндпоинтов

Сверено с `docs/architecture/api-ui-matrix.md` (реестр «сервер умеет / человек видит»). Действия на макетах 6a, у которых на сервере ручки **нет** — помечены бейджем прямо на экране:

- **Возврат переплаты** (`6a: Возврат и вне плана`). В домене есть `overpaid` и он попадает в сводку смены и в реестр чеков, но эндпоинта возврата нет. Нужно: `POST /api/t/:id/refund` c `{personaId, amount, method}`, идемпотентный ключ, запись в журнал, уменьшение `netRevenue`. Правило «кому» — последнему плательщику: он и переплатил.
- **Добавление стола в план зала** (там же). `hall.json` читают и сервер, и клиент; ручки на запись нет. Нужно: `POST /api/hall/tables` c `{id, zoneId, seats, waiterId}` и перечитыванием конфига без разрыва открытой сессии стола.
- **Фискальный чек** (`6a: Чек и предоплата`). Состояние «ждём чек из кассы» требует статуса от кассы через `PosAdapter` — сейчас 54-ФЗ не пробивается вовсе (это зафиксировано в `payments-fiscal.md` и в «известных прочерках» матрицы).
- **Предоплата** — переключатель заведения; на сервере `pay` уже умеет всё нужное, менять надо порядок шагов на клиенте и настройку заведения.
- **Сервисный вход по `mtoken`** (`6a: Экран недоступен`). Токен работает, но интерфейс о нём молчит — нужна только клиентская индикация, серверной работы нет.

Уже реализовано и на макетах помечено как редизайн: `NoAccess` из `apps/web/src/staff/StaffGate.tsx` (заголовок «Экран недоступен», текст «{имя}, роли «{роль}» раздел «{экран}» не открыт», кнопки «К своему экрану» / «Выйти из смены»), права — `packages/domain/roles.ts` (`PERMISSIONS`: у повара `kitchen, start, ready, serve, dismiss`; у официанта плюс `hall, table, ack, close, clean, cash`; `reset` и `log` — только менеджер; `ROLE_LABEL` = Менеджер / Официант / Повар).
